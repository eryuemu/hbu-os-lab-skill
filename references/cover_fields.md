## 2. 封皮下划线保全技术规范

在 Word OpenXML 中，封皮上的下划线是依靠 `<w:u w:val="single"/>` 实现的。

为了保证视觉居中且横线连贯，标准 Run (`<w:r>`) 结构应为：
```xml
<w:p>
  <w:pPr><w:spacing w:before="60" w:after="60"/></w:pPr>
  <!-- 前置固定文本标签 -->
  <w:r>
    <w:rPr><w:rFonts w:eastAsia="等线"/><w:sz w:val="24"/></w:rPr>
    <w:t>姓名/学号：</w:t>
  </w:r>
  <!-- 带单下划线的填写内容（左右留适量空格以延长下划线） -->
  <w:r>
    <w:rPr>
      <w:rFonts w:eastAsia="等线" w:ascii="Times New Roman"/>
      <w:u w:val="single"/>
      <w:sz w:val="24"/>
    </w:rPr>
    <w:t xml:space="preserve">         张三 20251701xxx         </w:t>
  </w:r>
</w:p>
```

## 3. 封面后多余空白页（第 2 页空白）的根源与程序化根除

### 3.1 产生根源
1. 原始模板封皮最后一行（“实验成绩： 教师签字：”）下面，默认包含 2~3 个空的换行段落（`<w:p><w:pPr>...</w:pPr></w:p>`）。
2. 在空段落之后，放置了一个硬分页符：`<w:p><w:r><w:br w:type="page"/></w:r></w:p>`。
3. 当用户或程序在封皮填入文字（尤其当行间距或字号微调、或者填入了稍长字符后），封面的总高度刚好超过了第 1 页的有效页面高度。
4. 此时，**多余的空段落和那个分页符被挤到了第 2 页**。分页符在第 2 页生效，强制将后面的正文大表格推到了第 3 页。
5. 结果：**第 2 页沦为除了几个换行符以外没有任何内容的纯空白页**。

### 3.2 程序化根除方案
在构建脚本 `build_report.py` 中：
- 遍历封皮段落，定位到包含 `w:type="page"` 的段落。
- 将该分页符前面的空段落（没有任何文本且没有下划线的 `<w:p>`）直接剔除。
- 确保分页符紧贴封皮最后一行，或者用分页符替换掉封皮底部的多余空行。
- 这样，封皮刚好稳定在一整页内，分页后正文表格稳定出现在第 2 页，彻底消灭第 2 页空白页。
